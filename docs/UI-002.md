# UI-002 — OSAP Design System

> Sistema de diseño de OSAP: color, tipografía, espaciado, componentes y estilo
> visual. Framework-agnóstico por diseño: los **tokens** se expresan como
> variables CSS (`--osap-*`) con mapeo opcional a Tailwind, y los **componentes**
> se documentan por anatomía, estados y contrato — no por implementación.
> Una vez publicados, los tokens y nombres de componente son estables.

Compañero de `UI-001` (UX/navegación). Este documento define **cómo se ve**;
UI-001 define **qué hay** y **cómo fluye**.

---

## 1. Identidad visual

OSAP es un motor de adquisición de partituras para coros: precisión, calma y
claridad de una partitura impresa.

- **Precisión** → rejilla estricta, métricas de 4 px, componentes quirúrgicos.
- **Música clásica** → serif de presentación + acento "latón", evocando una
  portada de partitura.
- **Foco** → el contenido (el score) protagoniza; el chrome (UI) se retira.

Leitmotiv: **"La partitura es la estrella; la interfaz es la mesa de atril."**

| Principio  | Aplicación                                             |
|------------|--------------------------------------------------------|
| Calma      | Fondo cálido, alto contraste, mínima decoración        |
| Precisión  | Alineación en rejilla, espaciado consistente           |
| Estado     | Cada operación larga es un stepper vivo (ver §7)       |
| Escritura  | Serif para títulos, sans para interfaz, mono para IDs  |

### 2.1 Sistema de tokens

### 2.2 Mapeo de estados de dominio → color

| Estado        | Color                        |
|---------------|------------------------------|
| `ready`       | `success`                    |
| `streaming`   | `info`                       |
| `downloading` | `accent`                     |
| `not_present` | `text-subtle` / neutro       |
| `error`       | `danger`                     |
| Job `completed`  | `success`                 |
| Job `running`/`downloading`/`parsing`/`validating` | `primary` (indicador activo) |
| Job `failed`  | `danger`                     |
| Job `cancelled`| `text-muted`                |

### 2.3 Contraste y accesibilidad

- Texto sobre fondo: ≥ **4.5:1** (WCAG AA). Los pares `primary`/`accent` sobre
  superficies se usan solo para acentos, no para texto de cuerpo.
- `--osap-focus` visible siempre (anillo de 2 px + offset 2 px), nunca suprimido.
- Modo oscuro es un cambio de tokens, no un recorte visual.

## 3. Tipografía

Dos familias + una monocspaciada. Tipografías de código abierto (Google Fonts).

| Familia       | Fuente          | Uso                                  |
|---------------|-----------------|--------------------------------------|
| Display       | `Lora` (serif)  | Títulos de obra, pantalla, encabezados |
| UI            | `Inter`         | Interfaz, cuerpo, botones, tablas    |
| Mono          | `JetBrains Mono`| IDs (`job_123`), checksums, tokens   |

Tamaños (escala fluida, `clamp`):

| Escala      | Tamaño    | Línea   | Uso                                   |
|-------------|-----------|---------|---------------------------------------|
| `display`   | clamp(2rem, 4vw, 2.75rem) | 1.15 | Título de pantalla (serif) |
| `title`     | 1.5rem    | 1.25    | Título de sección/obra (serif)        |
| `heading`   | 1.125rem  | 1.3     | Encabezado de tarjeta                 |
| `body`      | 0.9375rem | 1.55    | Texto de interfaz                     |
| `small`     | 0.8125rem | 1.5     | Metadatos, etiquetas                  |
| `caption`   | 0.75rem   | 1.4     | Notas, tiempos                        |
| `mono`      | 0.8125rem | 1.4     | IDs, rutas, checksums (mono)          |

Reglas:
- El título de **obra** siempre es serif (`Lora`); los IDs siempre `JetBrains Mono`.
- Peso máx. `600` para UI (evitar negritas gruesas en pantalla).
- Ancho de línea de texto: 60–75 caracteres.

## 4. Espaciado, radio, elevación, bordes

### 4.1 Espaciado (base 4 px)

`space-1..10 = 4, 8, 12, 16, 24, 32, 40, 48, 64, 96`. Regla de uso:
`padding` interno ≥ `gap` entre elementos, y la escala se recorre de uno en uno.

### 4.2 Radio

| Token          | Valor  | Uso                               |
|----------------|--------|-----------------------------------|
| `--osap-radius-sm` | 6 px | chips, badges, inputs           |
| `--osap-radius-md` | 10 px | botones, tarjetas              |
| `--osap-radius-lg` | 16 px | modales, paneles               |

### 4.3 Elevación (sombra)

| Token           | Sombra ligera                              | Oscura                              |
|-----------------|--------------------------------------------|-------------------------------------|
| `--osap-shadow-sm` | `0 1px 2px rgb(0 0 0 / 0.05)`            | `0 1px 2px rgb(0 0 0 / 0.4)`        |
| `--osap-shadow-md` | `0 4px 12px rgb(0 0 0 / 0.08)`           | `0 6px 18px rgb(0 0 0 / 0.5)`       |
| `--osap-shadow-lg` | `0 12px 32px rgb(0 0 0 / 0.12)`          | `0 16px 40px rgb(0 0 0 / 0.6)`      |

Preferir **borde** a sombra para separar (diseño "plano de partitura"); usar
sombra solo para elevación jerárquica (modales, menús).

### 4.4 Bordes

- Grosor estándar: **1 px** (`--osap-border`); destacado **1.5 px**.
- Un borde bajo en superficies basta; evitar `box-shadow` duplicada.

---

## 5. Iconografía

- Iconos **UI**: set lineal (1.5 px), 20×20, trazo redondeado — p.ej. Lucide.
- Iconos **musicales** (pentagrama, corcheas, clefs): vía **SMuFL** con fuente
  Bravura/Noto Music para fidelidad tipográfica; nunca emoji para símbolos de
  notación.
- Uso semántico: los iconos acompañan, no sustituyen, el texto en acciones
  primarias.

## 6. Componentes

Cada componente se documenta con **anatomía**, **estados**, **tokens** y
**reglas**. Los nombres son estables y reutilizables en toda la app.

### 6.1 Botón

| Variante   | Fondo               | Texto            | Borde |
|------------|---------------------|------------------|-------|
| `primary`  | `--osap-primary`    | `--osap-on-primary` | —   |
| `secondary`| `--osap-surface`    | `--osap-text`    | `border-2` |
| `ghost`    | transparente        | `--osap-text`    | —     |
| `danger`   | `--osap-danger`     | `#FFF`           | —     |

Estados: `default`, `hover`, `active`, `focus` (anillo), `disabled` (opacidad
0.5, sin interacción), `loading` (spinner inline, acción bloqueada).
Tamaños: `sm` 32 px / `md` 40 px / `lg` 48 px.

### 6.2 Campo de texto y select

- Alto `40 px`; borde `--osap-border`; `focus` → borde `--osap-primary` +
  anillo.
- Placeholder en `text-subtle`; etiqueta en `small`/`body`.
- Estados: `default`, `focus`, `disabled`, `error` (borde danger + mensaje),
  `with-icon`, `search` (icono + `Esc` para limpiar).

### 6.3 Tarjeta de obra (card)

Anatomía: título serif → metadatos (género · voces · año · licencia) → chips de
formato (`[MusicXML] [PDF]`) → acciones. Elevación `shadow-sm`, radio `md`.

### 6.4 Chip / Badge

Ronda (`radius-sm`), 1–2 palabras. Usos: formatos, licencias, voces, estado.

| Tono         | Fondo                | Texto               |
|--------------|----------------------|---------------------|
| `neutral`    | `--osap-surface-2`   | `--osap-text-muted` |
| `primary`    | `--osap-primary-soft`| `--osap-primary`    |
| `accent`     | `--osap-accent-soft` | `--osap-accent`     |
| `success`    | success 15%          | `--osap-success`    |
| `danger`     | danger 15%           | `--osap-danger`     |
| `info`       | info 15%             | `--osap-info`       |

### 6.5 Tabla de jobs / datasets

Columnas: nombre, estado (badge + dot), progreso, tiempo, acción. Fila
seleccionable; hover sutil (`surface-2`). IDs en `mono`.

### 6.6 Modal

`overlay` (negro 40%), panel centrado (radio `lg`, `shadow-lg`), ancho máx
`600 px`. Cierre por `Esc`, clic fuera y botón. Foco atrapado; `aria-modal`.

### 6.7 Toast / Notificación

Aparece en esquina inferior; duración automática (4 s, configurable). Tipos:
`info`, `success`, `warning`, `danger`. Icono de tipo + mensaje + acción opcional.

### 6.8 Navegación lateral (Shell)

Ancho `240 px`; colapsable a `64 px`. Secciones de UI-001. Elemento activo =
fondo `primary-soft` + marcador izquierdo `primary`. Contenido scrolla
independiente.

### 6.9 Skeleton / Loading

Formas de tarjeta con shimmer suave (opacidad pulsante). Nunca bloquear
navegación; reemplazar en su sitio al cargar.

## 7. Componente firma: JobStepper

De UI-001, materializado. Cada `Job` (resolución, descarga, verificación) se
reduce en un stepper conducido por eventos.

```
   [✓] Encolado     ◉ Corriendo     ○ Descargando   ○ Parseando   ○ Validando
                     ██████████
                       100%
```

- Cada paso muestra icono `✓`/`◉`/`○` según `done`/`active`/`pending`, y una
  barra de progreso en el paso activo.
- Colores: `done` → `success`; `active` → `primary` (latido sutil); `failed` →
  `danger`; `cancelled` → `text-muted`.
- No usa timing; solo los últimos eventos recibidos (ver `UI-001 §8`).

## 8. Estados transversales

| Estado   | Directriz                                                  |
|----------|------------------------------------------------------------|
| Carga    | Skeleton local; no cambiar layout bruscamente              |
| Vacío    | Icono + mensaje + CTA (p.ej. "Buscar una obra")            |
| Error    | Mensaje del proveedor/dataset + botón **Reintentar**       |
| Offline  | Bandea en proveedores; acciones online deshabilitadas      |

---

## 9. Movimiento

- **Duración:** `120ms` micro (hover/focus), `200ms` estándar (paneles),
  `300ms` entrada de modales. Curva `cubic-bezier(0.2, 0, 0, 1)`.
- **Reducido:** respetar `prefers-reduced-motion` (desactivar shimmer/latido).
- El latido del stepper activo es sutil (1.5 s ciclo) y solo en estado `running`.

---

## 10. Modo oscuro

- Cambio de tokens `--osap-*` (§2.1); misma tipografía, radio y espaciado.
- Seguir `prefers-color-scheme` + toggle en Configuración (persistido).
- Los scores/música conservan su propio fondo; el chrome se adapta.

---

## 11. Mapeo a Tailwind (opcional)

Si el proyecto adopta Tailwind, cada token se expone en el tema:

```js
// tailwind.config.js (esquema)
theme: {
  extend: {
    colors: {
      paper: "var(--osap-bg)",
      surface: "var(--osap-surface)",
      ink: "var(--osap-text)",
      primary: "var(--osap-primary)",
      accent: "var(--osap-accent)",
      success: "var(--osap-success)",
      // ...
    },
    fontFamily: { display: ["Lora", "serif"], ui: ["Inter", "sans"], mono: ["JetBrains Mono", "monospace"] },
  },
}
```

---

## 12. Criterios de aceptación

1. Ningún color/tamaño hardcodeado fuera de los tokens `--osap-*`.
2. Contraste AA en todos los pares texto/fondo.
3. `prefers-reduced-motion` y modo oscuro soportados.
4. Los nombres de componentes y tokens quedan congelados tras publicar.
5. React puede implementarse sin decisiones de estilo pendientes.
